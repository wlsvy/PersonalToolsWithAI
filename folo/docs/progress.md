# Folo nvim 플러그인 진행 내역

Folo CLI를 감싼 Neovim 플러그인의 작업 기록입니다. 설계는 [nvim.md](nvim.md), [preview.md](preview.md), [ai.md](ai.md)에 있습니다.

## 완료한 작업

| 단계 | 내용 | 커밋 |
|---|---|---|
| 1 | 기존 RSS 플러그인을 학습용 샘플 `rss_sample`로 이름을 바꿨습니다. | `3887368` |
| 2 | 타임라인, 본문, 읽음 전환을 담은 플러그인을 추가했습니다. | `0fe0e62` |
| 3 | 카테고리 선택, 컬렉션 보기, 원문 추출을 추가했습니다. | `7ed4bff` |
| 4 | 좌우 분할 미리보기, curl과 Chrome 원문 가져오기, 다중 선택과 일괄 열기를 추가했습니다. | `52d0e6d` |
| 5 | `?` 도움말 팝업을 추가했습니다. | 이 문서를 추가한 커밋 |
| 6 | AI 요약과 번역 큐, 자식 항목 표시, 파일 저장을 추가했습니다. | 이 문서를 추가한 커밋 |
| 7 | `:Folo`를 `Folo Dashboard` 탭으로 바꿨습니다. 설계는 [dashboard.md](dashboard.md)에 있습니다. | 대시보드 문서를 추가한 커밋 |

## 이번 작업의 주요 결정

- 결과는 임시 버퍼가 아니라 Neovim 캐시 폴더의 파일로 저장했습니다. 시간과 사용량이 드는 결과를 재시작 후에도 유지하기 위해서입니다.
- 파일을 직접 열지 않고 미리보기 버퍼에 내용을 넣어 표시합니다. 웹 글에서 나온 AI 출력이 modeline이나 자동 명령을 건드리지 않게 하기 위해서입니다.
- 크롬 확장의 프롬프트와 실행 방식을 그대로 재사용했습니다. 도구를 모두 끄고 전용 프로필로 실행합니다.
- 원문을 읽지 못한 글은 AI를 호출하지 않고 실패로 표시합니다. 링크 한 줄로 요약하면 내용이 지어질 수 있기 때문입니다.
- 작업 취소 기능은 넣지 않았습니다. 대신 11개 이상을 한 번에 요청하면 먼저 확인합니다.

## 검증 상태

- 자동 테스트 `cli_test`, `article_test`, `ai_test`, `render_test`가 통과했습니다. 모두 가짜 CLI, 가짜 curl, 가짜 Chrome, 가짜 Claude를 사용합니다.
- 실제 Folo 계정의 타임라인과 본문 표시는 사용자가 확인했습니다.
- 실제 Claude 호출, 실제 사이트의 원문 추출, 헤드리스 Chrome 렌더링은 아직 확인하지 못했습니다. 샌드박스가 외부 네트워크와 홈의 로그인 정보를 막기 때문입니다.

## 다음에 확인할 것

1. 목록에서 `s`를 누르면 요약이 만들어지고 자식 항목이 나타나는지 확인합니다.
2. 자식 항목에서 `t`를 누르면 번역이 요약 아래에 붙는지 확인합니다.
3. `Not logged in`이 나오면 `CLAUDE_CONFIG_DIR=~/.claude-clip claude`로 로그인합니다.
4. 긴 글의 번역이 끊기거나 시간 제한에 걸리는지 확인합니다.
5. 미리보기의 `R`이 Chrome을 찾는지 확인합니다.

## 알려진 한계

- 진행 중인 작업은 취소할 수 없습니다.
- Neovim을 종료하면 진행 중인 작업이 중단되고 결과는 저장되지 않습니다.
- 본문 추출은 단순한 규칙이라 사이트에 따라 메뉴가 섞이거나 내용이 빠질 수 있습니다.
- 내부망 주소 차단은 URL에 적힌 호스트만 검사합니다.
