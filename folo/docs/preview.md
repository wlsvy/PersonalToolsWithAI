# Folo 분할 화면과 원문 미리보기

상세: [preview.ai.md](preview.ai.md)

## 목적과 배경

피드에 따라 본문이 링크 한 줄뿐이라 Neovim에서 내용을 읽을 수 없습니다. 목록을 훑으면서 내용을 바로 확인하고, 고른 글을 한꺼번에 브라우저로 열 수 있어야 합니다.

## 결정 사항

- 모든 목록 명령은 좌우로 나눈 화면을 엽니다. 왼쪽은 글 목록이고 오른쪽은 미리보기입니다.
- 커서를 옮기면 미리보기가 자동으로 바뀝니다. 빠르게 움직일 때는 잠시 기다렸다가 마지막 글만 불러옵니다.
- 미리보기만으로는 읽음 처리하지 않습니다. 커서가 지나간 글까지 읽음이 되면 안 되기 때문입니다. Enter로 미리보기에 들어갈 때 읽음 처리합니다.
- 본문이 부족하면 피드 본문, Folo 추출, curl 순서로 원문을 가져옵니다. 피드 본문은 지우지 않고 그 아래에 원문을 덧붙입니다. 원래 짧은 글을 잘못 판단해도 내용을 잃지 않기 위해서입니다.
- 헤드리스 Chrome은 사용자가 키를 눌렀을 때만 실행합니다. 커서 이동만으로 낯선 사이트의 JavaScript를 실행하면 안 되기 때문입니다. 로그인 정보가 섞이지 않도록 매번 빈 프로필을 씁니다.
- 내부망 주소는 자동으로 가져오지 않습니다. 피드에 적힌 주소만으로 내 PC의 내부 서비스에 요청이 나가면 안 되기 때문입니다.
- 목록에서 여러 글을 선택하고 한 번에 브라우저로 열 수 있습니다. 많이 열 때는 먼저 확인을 받습니다.
- 물음표 키로 현재 화면의 동작과 단축키 설명창을 열고 닫습니다. 설명창은 포커스를 가져가지 않아 열어 둔 채로 목록을 움직일 수 있습니다.

## 범위

- 하는 것: 분할 화면, 자동 미리보기, 원문 가져오기, 브라우저 렌더링, 다중 선택, 일괄 열기입니다.
- 하지 않는 것: 디스크 캐시, 이미지 표시, 로그인이 필요한 페이지 읽기, 선택한 글의 일괄 읽음 처리입니다.

## 순서

1. 원문을 가져오고 본문을 추려 내는 계층을 만듭니다.
2. 목록 화면을 분할 화면과 미리보기로 바꿉니다.
3. 다중 선택과 일괄 열기를 추가합니다.
4. 자동 테스트로 확인하고, 실제 계정 점검은 사용자가 진행합니다.

## 남은 위험

- 본문 추출은 단순한 규칙이라 사이트에 따라 메뉴가 섞이거나 내용이 빠질 수 있습니다.
- 차단이나 로그인이 필요한 사이트는 Chrome으로도 읽지 못할 수 있습니다.
- 자동 미리보기는 글을 볼 때마다 해당 사이트에 요청을 보내므로, 사이트가 내 접속을 기록할 수 있습니다.

## 확장성 결정

사용자가 문서 작성 후 바로 진행하도록 요청해 아래 기본값으로 진행합니다. 모두 설정으로 바꿀 수 있습니다.

1. 원문 가져오기: curl을 자동으로 쓰고 Chrome은 수동으로 씁니다. 다른 추출 도구를 쓰도록 바꾸는 플러그인 구조는 만들지 않습니다.
2. 자동 미리보기: 기본으로 켭니다. 원문 자동 가져오기만 따로 끌 수 있습니다.
